# PA4 implementation plan and final independent audit

## Scope, history and reconstructed architecture

- **Stage base:** `4c7867d2d7d0e26237fcab01eb8d4ea0af777242`. **Audit-before-fix:** `02984372139e4a35d9b1272aa81262bc0f7c843d`. The audit covers the PA4 implementation and every later PA4/PA3 source change through the final audit commit. The earlier stage-entry and checkpoint commits are history, not substitutes for this review.
- **Actual PA4 path:** `preproc.cpp` reads an immutable source buffer; `PPTokenizer`'s phase-1/2 cursor and phase-3 lexer deliver typed, borrowed callbacks; `FileStream` accumulates only the current logical line; `process_line` separates directives from text; active text flows into the macro rescanner; expanded tokens are sent directly to the reusable PA2 `IPPTokenStream` phase-5/7 consumer; the CLI's posttoken-record text is only the required observation adapter. `evaluate_if` converts expanded typed tokens directly to PA3's controlling-expression API. Token dumps are not read back as phase input.
- **Representative trace:** `pa4-audit-flow.t` includes a header defining `TYPE`, `SCALE`, `JOIN`, and `TEXT`. `TYPE` expands to the `int` simple token; `JOIN(value, 0)` pastes and rescans to identifier `value0`; `SCALE(BASE)` expands through two object/function macros and phase-7 converts both `7` tokens to `int` literal bytes; `TEXT(value0)` stringizes the raw argument and phase-7 emits the six characters plus terminator. The checked output is `student.tests/pa4-audit-flow.expected`. This covers include path, source/file identity, identifier lookup, argument expansion, paste, stringize, typed posttoken conversion, and output ownership end to end.
- **Ownership and identity:** each `PPTokenizer` borrows its immutable source until that file's callbacks and recursive processing complete. The stream does not retain a whole translation-unit token graph: normal processing retains one logical line plus only a suffix deferred for an incomplete function-macro invocation or `_Pragma`; includes recurse through the same translation-unit state. Identifier spellings are interned to stable 32-bit IDs; macro definitions/parameters, macro-table keys, and recursion-unavailable sets use those IDs. The identifier interner and macro table use geometrically grown flat open-addressed storage. Tokens carry compact source-file IDs and paint handles, not owning `shared_ptr`s. A TU-local paint slab is reset after a completed line, except while deferred tokens still reference it. Names and macro replacement lists live until their owning TU/macro is destroyed. Non-identifier spellings are still owned where translation or synthesis makes a source slice insufficient; the callback interface supplies borrowed spellings, not normalized source offsets.
- `expand` moves its input into a deque and releases the input vector before rescanning. Raw arguments, cached prescans, substitution and paste temporaries are local to the invocation; token-paste retokenization is limited to the pasted spelling. One shared work counter covers a recursive argument-prescan tree (10,000,000 visited tokens), with a depth guard of 256; include recursion is bounded at 128. These are resource/termination guards, not benchmark acceptance gates. They exceed the C++11 Annex B minima for macro nesting (256) and include nesting (15); no course fixture hits a limit. Work is otherwise proportional to consumed source/directive/expansion tokens, with bounded maximal-munch operator candidate groups.
- **Whole-stage scope boundary:** PA4 has no parser, declaration/type/template graph, specialization cache/worklist, LowIR, MIR, optimizer, allocator, native code or ELF object writer. `cppgm++` remains the later-stage not-implemented driver. Thus the spec's declaration/template-to-ELF trace, optimization legality/profitability/invalidation, ABI/unwind, allocation, and generated-program runtime/text acceptance cannot be certified by PA4 and are explicitly not claimed. The applicable PA4 executable benchmark is `preproc`; its own latency, peak RSS and ELF `.text` are measured below. No generated C++ executable exists from which to measure user-program runtime or text size. Later stages still owe those reviews and telemetry.

## Findings and changes

- **Canonical identity / allocation finding:** the checkpoint interned token identifiers but still keyed macro lookup and recursion paint by rendered names; each token also owned `shared_ptr` file/paint state. This conflicted with canonical ID lookup and the spec's hot-node ownership direction. Converted macro table keys, macro parameter identities and paint membership to interned IDs; replaced node-based identifier and macro maps with flat geometrically-grown tables; precomputed each replacement token's parameter index once at definition time rather than allocating a string/ID hash map for every invocation; replaced per-token file ownership with stable TU-local file IDs and per-token paint ownership with compact handles into a TU-local slab. Macro paint storage is bulk-reset only when no deferred token can refer to it. A 240-name define/undef/redefine reducer forces interner and macro-table growth, deletion, re-insertion and lookup; exact independently generated posttoken output passes (`$RALPH_ARTIFACT_DIR/pa4-final-audit/reducer/`).
- **Work-bound finding:** the 10-million token-expansion guard was local to each recursive argument prescan. It now shares one counter across the complete recursive expansion tree, so nested prescan cannot multiply that budget by recursion depth. The per-expression enum lookup and PA tokenizer's operator scan are also bounded by enum comparisons and a fixed first-character candidate group, respectively.
- **Inherited PA3 handoff:** final source commit `0298437` changes only `PPTokenizer::scan_operator` and PA3's operator checks. Operator candidates are grouped by first character in maximal-munch order (the `<::` exception is preserved); mismatch work is bounded by the largest group instead of probing every punctuation spelling. The expression parser now compares already-classified operator enums instead of repeatedly mapping strings. This audit inspected the complete source diff, maximal-munch ordering, and special case, and rechecked the exact stress output. No PA3 behavior/reference changed.
- No course reference, test input, status sidecar, comparison rule, or coverage was changed. No reference correction was indicated; the preserved personal reducer `student.tests/pa4-stringize-backslash.t` agrees with C++11 N3337 §16.3.2 [cpp.stringize]/2: original preprocessing-token spelling is retained, and `\`/`"` escaping applies to spellings of literal tokens. The standalone backslash is not doubled; phase 5/7 decodes the resulting `\\n` as newline (`3A20400A00`). Bundle revision remains `c2f713cd70d06170632bfde3e75dd6fe1aa44d98`.

## Performance evidence and acceptance

- **Protocol / artifacts:** final A is the frozen pre-audit `preproc` from commit `02984372139e4a35d9b1272aa81262bc0f7c843d`, SHA-256 `7a81c0ab527bc42fcf2f962788f47023ecc9be2fb5c7b6684d73990ca86b7a20`; final B is the audited build, SHA-256 `7e55a64f9c80d55ac43aeb79c67615edb3641e3bb54f4b5a8f018b19c89a3ca3`. Same `g++ -std=gnu++11 -Wall -O3` Makefile build with `CPPGM_TEST_RUNNER=0`; same frozen input, output path spelling, and binary throughout each comparison. Timings pin both A and B to CPU 0. Each workload has output equivalence checked before timing, eight A/A pairs, seven wall-time ABBA blocks, and separate A/B/B/A/A/B RSS samples. Full binaries, inputs, outputs, scripts, sizes, hashes, build logs and every observation are preserved under `$RALPH_ARTIFACT_DIR/pa4-final-audit/` (`measurements-pinned.json` is the final claim; earlier noisy and pre-final runs are retained separately).
- **Identifier-throughput workload:** 6,600,000 input bytes, SHA-256 `c215886ae78c284cef477c89c6f8615670983b34ff186e5b844ade1c02ed8527`; identical output 9,900,033 bytes, SHA-256 `c4f4e58f765c3519901ddc57fd8144eff33f60bb9389edd2f8a68ab69a7118d4` (the source path is part of the `sof` record). Peak RSS medians are 11,588/11,592 KiB; ranges overlap, so there is no material memory change.
- **Macro-heavy workload:** 5,534,683 input bytes, SHA-256 `99152c1af01cf7759ac84a888ae1c367ac50c87952016690a7b578a2f6ac0b4b`; 150,000 nested function/object expansion, paste and stringize lines. - PA1–PA4 have no mandated numeric text/RSS/latency gates. PA1's prior 1% text/RSS thresholds were unsupported self-imposed gates and remain non-binding measurements (as reclassified in `pa1/plan.md`); PA2/PA3/PA4 historical single-run values and the below-noise PA4 result are retained as observations, not exit requirements.
