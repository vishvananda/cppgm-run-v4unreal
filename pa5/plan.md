# PA5 implementation and final independent audit

## Scope, history, and reconstructed architecture

- **Stage base:** `4c77c279c09fb196ee905efad07594c8524b28a4` (PA4 audit). **Implementation:** `6da4d4bf738133b09adf774fc7b97e7aef25bf39`. **Prior checkpoint/evidence:** `149626ca043a196f05cfeb61d82b2fe118f00df2`. This review independently traces the implementation and the audit changes below; checkpoint conclusions are context, not a substitute for this review.
- **Production path:** inputs are processed one translation unit at a time. `Preprocessor::process_file` owns one immutable shared source buffer while `PPTokenizer` phase 1/2/3 streams typed callbacks into the preprocessor's current-line/macro pipeline. Macro expansion writes directly into the typed PA2 `PostTokenStream`; text token dumps are never an intermediate. The PA5 collector appends one compact lookahead tape (`PostTokenRecord` IDs/kind/source point) and interns each spelling and source-file name once in flat, geometrically grown tables. `TokenView` indexes this tape; the driver/parser do not create successive owning preprocessing/post/recognition/parse token vectors. The recursive-descent parser constructs `SyntaxNode`s in one TU-owned arena. `SyntaxTree` takes the source/header buffer owners, and `SyntaxTree.cpp` renders the exact assignment dump as a final adapter. The driver releases tree, token tape and TU source set before processing the next input.
- **Representative data and ownership trace:** `student.tests/pa5-audit-location-source.cpp` defines `DECL` as `int audited_value` and uses it on line 2. `PPTokenizer` reports the original byte offset; the preprocessor transfers the expansion-origin point to replacement tokens; PA2 conversion emits compact `int`/identifier records; parsing builds the declaration at that location; the returned tree owns the same immutable source bytes. `student.tests/run-pa5-audit.sh` independently checks token file/line/column/offset, tree file/offset, and byte identity of the retained source buffer. `student.tests/pa5-parser-smoke.cpp` separately traces a namespace typedef and a function-template body through preprocessing, parsing and deterministic rendering.
- **Identity, scope, and lifetime:** input spellings are interned before parser lookup. `FlatNameSet` stores stable spelling IDs in flat open-addressed sets instead of ordered string nodes. Type/value/template lookup observes nearest lexical category; parameter-clause frames are RAII-bounded and parameters are rebound only for the function/lambda body and constructor-initializer region. Template-parameter frames expire after the declaration. Class member type/template facts are retained for qualified lookup/member contexts rather than promoted to the outer unqualified frame; `student.tests/pa5-audit-parameter-scope.cpp` verifies both parameter shadowing and that `Holder::hidden_type` does not turn an unqualified `hidden_type * pointer;` after the class into a declaration. Syntax child vectors use a TU arena and bulk release. Shared ownership is only at source-file granularity, not per token. AST locations pack file identity and byte offset; line/column remain on compact token records and can be derived from retained buffers. AST label text remains an owning syntax/rendering payload; this PA5 tree is not yet the later canonical semantic graph.
- **Parsing work bound:** known template/value facts resolve ordinary cases directly. Only unresolved `<` candidates use lookahead. Delimiter-aware top-level statement/body boundaries stop failed candidates; a TU-wide monotonic budget caps total speculative visits at four token visits per input token, including after parser cursor rollback. Exhaustion takes the conservative relational parse for that unresolved case. This bounds speculative candidate work by O(tokens); it is not an optimization or language-validity exit gate.
- **Stage boundary and limitation:** PA5 emits an AST only. There is no semantic type/declaration graph, complete namespace/ADL/using-edge lookup, specialization demand/cache/worklist, LowIR/MIR, optimizer, native backend, ELF user object, or generated C++ executable here. The syntax-only namespace category fallback still promotes namespace facts into enclosing category frames for the PA5 tested using/import cases; this is not full C++ namespace lookup. Likewise, class qualified-name categories are a limited lexical approximation, not owner-complete semantic lookup. The exact dump retains some template/name payload in syntax label text. These are explicit PA6 handoffs: replace the fallback with indexed namespace/class/using edges and canonical semantic identities, and consume structured nodes/ranges directly rather than parsing the dump. This audit does not claim those later mechanisms or the spec's full declaration/template-to-ELF trace as PA5 results.

## Findings and changes

1. **Unbounded parser lookahead:** before audit, each unresolved identifier followed by `<` could scan to the end of the TU, including across statements. Repeated relational expressions could make parser work quadratic. A frozen reducer of 8,000 distinct functions (`aN < bN`) took about 1.2 s; a single 8,000-argument comma-separated relational statement exercised the same-statement scan. The parser now tracks delimiters, stops at top-level statement/body boundaries, and caps aggregate speculative visits at `4 * token_count`. The budget is monotonic across rollback. Known templates bypass the heuristic; an exhausted ambiguous fallback is parsed as relational syntax. The separate relational and comma-relational A/B measurements below show repeatable benefit with byte-identical AST output.
2. **Parameter and class category leaks:** function parameter names were added to enclosing namespace/class sets, changing later parses when a parameter matched a class/template spelling. Template declarations also retained an unnecessary frame. Parameter clauses now have scoped category frames; function, constructor-initializer, lambda, and function-try regions rebind those facts only within their language scopes. The template declaration frame is discarded after the declaration. Class member categories are separated from unqualified lexical sets and retained for the limited qualified/member contexts. Nearest category wins, so local values shadow outer types/templates. The audit reducer verifies parameter-name shadowing and non-leakage of a class typedef.
3. **Owning post-token vectors and dropped locations:** the collector used per-token owning `kind`/`spelling` strings and ignored already-available source-file/line/column callbacks. `PostTokenBuffer` now retains compact typed records, stable spelling/file IDs, and source points in a flat interner. `PPTokenizer` forwards byte offsets; the preprocessor carries expansion-origin offsets and shares immutable source buffers with the collector. `SyntaxTree` owns those buffers while nodes retain packed file/offset anchors. This is one compact token tape for parser lookahead, not successive owning token/syntax/recognition streams.
4. **AST allocation and adapter ownership:** parser-created child vectors allocate from the TU arena with a bounded same-size free list and one bulk release point. The deterministic writer is separate from parsing; token vocabulary/view and arena storage have cohesive units. The output dump is unchanged. Scope category sets are flat and keyed by interned spelling IDs. AST label strings remain owned because they are the current PA5 syntax/dump payload; PA6 must not turn them into a dump-reparse transport.
5. No course inputs, references, status files, comparison rules, or test coverage changed. No reference output was proven wrong, so the reference-correction exception was not used; no bundle revision is involved.

The bounded-lookahead change has large, repeatable benefits on both affected relational workloads, well above their calibrated A/A spread and with byte-identical ASTs. No ordinary-declaration latency benefit is claimed: the paired run median is slower and has both favorable and unfavorable blocks. Peak memory is close on that ordinary input; it increases by about 8.2% on the relational-function stress and 3.7% on the single-statement reducer. `size -A` reports compiler `.text` 556,550 B (A) → 557,638 B (B), +0.20%; total sections 658,984 B → 663,953 B, +0.75%. These are the disclosed stage-scoped costs/benefits. PA5 has no mandated numeric latency/RSS/text limit or optimization-level work/growth budget; no unsupported percentage gate is invented. The parser's added speculative work is capped at 4T token visits, source/token/AST ownership remains TU-bounded, and outputs are unchanged. No executable user program is emitted in PA5, so generated runtime and user-code text size are inapplicable; compiler invocation latency, peak RSS and compiler `.text` are measured above.

**Inherited acceptance review:** `pa1/plan.md`'s former 1% tool text/RSS gates are already reclassified as unsupported self-imposed measurements. PA2/PA3/PA4 plans retain calibrated A/A/ABBA evidence and do not introduce mandated numeric gates. Their historical single-run or below-noise values remain observations, not exit requirements. PA5's previous identical-binary measurements remain preserved and are not represented as gains.
