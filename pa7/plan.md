# PA7 — final semantic-surface audit

## Stage, history, and acceptance boundary

- **Stage base:** `f4b2cdd351002ab973bad62dc4b16046b4937458` (PA6 final audit).
- **Implementation reviewed:** `6c41afc7c96c853b5ae247d492e0607c8e5ec389`; this audit also includes the cohesive fixes committed with this ledger.
- **Scope:** `cppgm++ --emit-semantics` is a frontend semantic-dump tool. PA7 emits no LowIR, native code, ELF object, or executable. Consequently generated-program runtime/text-size, native allocation, optimizer legality/profitability/invalidation, and optimizer work/growth budgets are **not applicable** in this stage; no runtime claim is inferred from a smaller dump or fewer IR nodes. Compiler invocation latency, peak RSS, and compiler text size are applicable and measured below.
- **Assignment boundary:** preserve PA5 AST/PA6 types output and the checked PA7 call/conversion/control-flow behavior. The stage has a narrow checked type-only function-template surface in addition to the README's stated non-template subset; general class-aware calls, constructors, templates, full demand scheduling, and object lowering remain outside this handout.

## Reconstructed architecture and data/ownership trace

1. The driver processes each source argument as a separate translation unit. The preprocessor streams into one compact `PostTokenBuffer`; the parser constructs one arena-backed `SyntaxTree` with compact source locations and shared immutable source-file buffers. It does not write tokens or syntax to text and read them back. The semantic model interns names and forms TU-local `NameId`, `TypeId`, scope, entity, signature, and overload-identity records from that same parsed tree. `--emit-semantics` retains the source-facing tree only until its semantic view has been written; model/tree/source owners die at the end of the TU. Other semantic modes can release the syntax arena after graph construction.
2. **Ordinary declaration and call trace:** `namespace n { int f(const int*); }` is preprocessed into compact tokens and parsed once; PA6 creates an indexed namespace scope, a canonical pointer/CV type and function entity/signature, and a name binding. In `n::f(p)`, PA7 resolves the qualified name through scope/name IDs, collects the same-scope overload bindings, classifies the argument conversion, selects a binding identity, and writes the resolved `callee`/argument expression as a deterministic view. The audit changed name-to-binding access to use the PA6 same-name index, so it visits candidates for the queried name rather than every binding in a wide scope.
3. **Demanded-template trace:** a checked `template<class T> T id(T)` creates a template-parameter scope, a stable type-parameter `TypeId`, and a function binding. A call or target-directed function-pointer use collects only candidates visible in its lexical/qualified owner scope, deduces `T`, substitutes the function type, records the demanded result for the output view, and releases this temporary state with the TU. Substitution and overload comparison now key template parameters by their canonical type IDs, not their rendered `"typename T"` spelling. This is the limited PA7 fixture behavior; PA7 does not implement general specialization state machines, non-type/template-template substitution, dependent-body rechecking, or definition/layout/emission demand.
4. The PA7 type adapter memoizes projections in a dense TU-local cache keyed by immutable semantic `TypeId`; equality between two canonical projections uses those IDs, and class/enum/member-pointer identity uses owner-scope IDs. The recursive projection links are non-owning pointers into a `CallSemantics`-owned `deque` arena, not per-expression `shared_ptr` trees. Synthetic qualification, decay, and substituted types are short-lived values in the same arena and are compared structurally when they have no canonical ID. The cache/arena dies with that translation unit. It is not a serialized type key or a process-global cache.
5. There is no PA7 semantic-text consumer in the production path. In particular, this stage does not trace a resolved expression to ELF because it has no lowering/object-writer implementation. The remaining handoff is explicit: the later C++-to-LowIR owner must consume or persist typed selected-declaration/conversion facts directly, must not parse this dump, and must trace that path through MIR/ELF when those surfaces exist.

## Findings and cohesive changes

| Finding from source/reproducer | Change and validation |
|---|---|
| PA6 bound condition declarations and `for` initializers to an enclosing block, so names leaked after `if` and `for`; a loop-init declaration also poisoned a following declaration with the same name. | Give `if`/`switch`/`while`/`for` statement regions their own block-scope identity and each noncompound selection/iteration substatement its own implicit block scope; make the PA7 visitor enter those exact scopes. Reducers verify condition visibility in both arms, independent unbraced sibling declarations, rejection after `if`/`for`/`do`, and legal reuse after a loop. C++11 N3485 §6 [stmt.pre], §6.4 [stmt.select], and §6.5 [stmt.iter]. |
| The first template implementation indexed candidates only by name across the whole TU. An unrelated/global template could be resurrected after a nearer object hid the name; qualified template lookup also missed its owner scope. | Index templates by `(owner ScopeId, interned NameId)`, combine templates only with the ordinary overload set in the resolved owner, and stop lookup when an ordinary non-function hides the name. Qualified owner resolution handles namespace and class prefixes. Type-parameter substitutions use `TypeId` keys. Reducers cover hidden, unqualified, qualified, and target-directed template use. |
| Conversion ranking collapsed different standard sequences to a few integer ranks. It treated pointer-to-`bool` as tied with pointer-to-`const void*`, made exact by-value vs reference sequences spuriously prefer one side, did not distinguish direct/temp reference binding, and ranked a reference conversion to ellipsis as no better. | Preserve standard rank plus qualification quality, binding form, and reference category; compare candidates pairwise across actual arguments. Qualification is better than pointer conversion; exact by-value/reference sequences can remain ambiguous; direct binding and rvalue-reference binding use their tie rules; an ordinary conversion remains better than ellipsis. Existing overload oracles and new reducers cover pointer/void/bool, lvalue/rvalue refs, conversion-created temporaries, and ellipsis. C++11 N3485 §13.3.3.2 [over.ics.rank], §8.5.3 [dcl.init.ref], §4.4 [conv.qual], and §4.10 [conv.ptr]. |
| Same-name binding lookup still scanned complete scopes; `BindingRef` construction reused the first overload's numeric binding index for every candidate. | Expose indexed same-name binding indices and source-location binding lookup from `SemanticModel`; use the actual index for each candidate. This keeps candidate work scoped to the queried name and gives each reference the correct `(ScopeId,binding-index)` pair. |
| Canonical type IDs were repeatedly expanded into fresh structural type trees; class/enum/member-pointer/function-cv comparisons could conflate distinct identity. | Cache the temporary PA7 type view by canonical `TypeId`, use canonical IDs for equality when both sides carry them, preserve class/enum/member owner-scope identity, include member-function cv in structural fallback, and key template parameters by their `TypeId`. The cache has a single-TU owner and no invalidation path because published model facts are immutable; synthetic derived types remain local and structural. |
| Literal type/bound views and `sizeof` were inaccurate for cases inside the available grammar: ordinary single-character literals were reported as `int`, integer-literal type selection ignored value/radix, escaped string spellings counted as source characters, leading-dot floating literals were misclassified, `sizeof(void/function/incomplete)` returned a fake size, references/enum underlying types were sized incorrectly. | Implement C++11 integer candidate-type selection for the x86-64 target, ordinary character-literal type, escape-aware string code-unit counts, leading-dot floating classification, rejection of invalid/incomplete `sizeof`, reference sizing, enum underlying size, and x86-64 member-pointer sizes (the latter follow the target Itanium C++ ABI, not a universal C++ object-size rule). Reducers cover boundary literals and escaped-string reference binding. C++11 N3485 §2.14.2 [lex.icon], §2.14.3 [lex.ccon], §2.14.5 [lex.string], §4.5 [conv.prom], and §5.3.3 [expr.sizeof]. |
| Duplicate `case`/`default` labels were not diagnosed, and member lookup could accept an enclosing namespace/global binding as if it were a class member. | Track converted integral labels and one default per active switch (nested switch frames are independent); require direct class ownership before base-member lookup. Reducers verify duplicate rejection, nested switch acceptance, unrelated member-pointer cast rejection, and global-not-member rejection. C++11 N3485 §6.4.2 [stmt.switch] and §5.7 [expr.ref]. |

All findings were fixed across the relevant semantic-scope, binding-index, conversion, and output paths. No checked-in fixture, reference, status sidecar, comparison rule, or test coverage was changed. No reference correction was needed; no reduced reference-output proof or reference-bundle revision applies. Manual C++11 behavior checks were considered alongside the cited standard clauses, not as a substitute for them.

## Complexity, work/growth, and performance evidence

- Preprocessing and parsing remain source/token proportional. Scope-location and name indexes are TU-bounded. Function candidate collection is proportional to visible same-name candidates; argument conversion work is proportional to candidates × arguments. Dominance comparison is O(V² × arguments) in the *actual viable overload set* (not a Cartesian product of unrelated declarations); no unsupported fixed overload-count threshold is imposed. Type projection caching is bounded by canonical types reached in the PA7 TU and is discarded at TU end.
- PA7 has no O-level optimization passes, executable generation, or optimizer pipeline-wide work/code-growth budget to assess. It does not claim native latency, runtime, or generated text size. The PA7 semantic executable's text growth is measured explicitly rather than used as a course pass/fail gate.
- The implementation's original frozen lookup-index experiment remains preserved in `pa7-performance-abba.csv` and `pa7-performance-measurements.csv`: same 404,882-byte/5,000-function-and-call input, equivalent 2,615,146-byte output, pinned `g++ -std=gnu++11 -Wall -O3` binaries, A/A and ABBA observations, peak RSS, and text size. That experiment isolated replacing linear scope-location/binding scans with indexes. Its six A/B observations show A at 17.13–29.65 s and indexed B at 0.38–0.39 s (about 97.9–98.4% lower); B peak RSS is about 3.5% higher and compiler `.text` grows 1,956 B (0.18%). The calibrated A/A pair spread is disclosed in the CSV; the improvement was much larger than that spread. This narrow historical claim is not conflated with the final audit comparison below.
- **Final audit A/B:** A is the frozen prior-stage executable from `6c41afc7c96c853b5ae247d492e0607c8e5ec389`, SHA-256 `892e5afc1a4c24234f63230d186a3c2ea46d2cda1c6bfcd8f987c566e70b3665`, 1,238,344 bytes. B is the final audited executable, SHA-256 `a869460dbad5a5dea101d997e34a8e8467bce4aac8aa457007d1327151291745`, 1,284,856 bytes. Both use the Makefile `g++ -std=gnu++11 -Wall -O3` build. Six A/A and six B/B calibration pairs plus six pinned CPU-0 ABBA blocks were measured; the fixed 20,000-function/call input is 1,706,709 bytes (`f96391a2…b19186`) and the A/B outputs are byte-identical, 10,546,922 bytes (`eddc30fd…9f9a7ca`). Every observation is in `pa7-final-audit-measurements.csv`; scripts, binaries, full hashes, outputs and JSON summary are under `$RALPH_ARTIFACT_DIR/pa7-final-audit/`.
- The final 20k calibration was noisy: A/A relative pair deltas ranged 2.15–61.68%; B/B ranged 0.25–42.34%. Six paired ABBA changes (B vs A) ranged **−11.06% to +5.31%**, median **+0.24%**; the spread overlaps calibrated noise, so **no final-audit latency benefit or regression claim is made**. Peak RSS medians are 118,642 KiB (A) and 118,454 KiB (B), −188 KiB (−0.16%) with overlapping ranges. `size` text is 1,101,175 B → 1,147,152 B (+45,977 B, 4.17%); the compiler binary grows by 46,512 B (3.76%). These costs are disclosed; PA7 has no mandated numeric latency/RSS/text threshold, so they are not converted into an unsupported gate.
- Executable runtime and generated-program text size are **not applicable**: PA7 produces only a semantic dump, not an executable. The required course suite is correctness/coverage validation, not the performance benchmark. No performance result here substitutes for later loop/memory/floating-point/self-hosting executable benchmarks.
