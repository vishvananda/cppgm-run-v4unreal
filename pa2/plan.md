# PA2 implementation plan and independent final audit

## Scope and design/spec alignment

- PA2 base: `a857f68d973bbb77bfaed770254340614fc36f50`; implementation checkpoint: `ebbd28aa090f7cee8a75b6726919c06a55204b46`; last checkpoint/measurement commit: `80dec77d01b1f66a9efc7742df870d75084b73e1`. This audit reviews the whole PA2 path, inherited PA1 token handoff, and the audit delta from `80dec77d01b1f66a9efc7742df870d75084b73e1`.
- `dev/posttoken.cpp::main` reads one immutable UTF-8 input buffer. `PPTokenizer` borrows it: `Phase12Cursor` validates/decodes UTF-8, maps trigraphs and splices lines with bounded lookahead (including the phase-2-mandated final newline); `Lexer` handles comments/newline events, directive/header-name context, maximal preprocessing tokens, UCN spelling, and calls the typed `IPPTokenStream` callbacks. Its logical lookahead is bounded by the largest UCN/operator probe. Raw-string scanning caps the delimiter at 16 characters, reads reverted physical source between quotes, then resets the cursor after the raw token. The production path does not construct the PA1 debug token text or serialize/reparse tokens.
- `PostTokenStream` is the direct event consumer. It classifies keywords/operators and converts pp-numbers and character literals during their callback. Whitespace/newline events are ignored as required. Its narrow `operator` context recognizes `operator""suffix` as an empty string token plus suffix identifier (the required literal-operator-id token boundary). It copies token spellings only for one maximal adjacent string-literal run; the next non-string event or EOF flushes that run. It resolves the run's encoding and UDL suffix, decodes scalar and escape values, encodes code units, appends the terminator, and passes bytes directly to `DebugPostTokenOutputStream`. The output class is the required text adapter, not an intermediate representation.
- Representative full ownership trace (also in `student.tests/pa2-audit-data-flow.t`): `u"𝄞" /* comment/newline */ "A\x42"_ud;` arrives as two string callbacks; phase-6 grouping retains both spellings. The explicit `u` selects UTF-16 for the ordinary second piece too. The scalar U+1D11E becomes D834 DD1E; `A` becomes 0041; numeric `\x42` contributes the single code unit 0042; the terminating code unit is 0000. The result is `array of 5 char16_t`, bytes `34D81EDD410042000000`, with the two source spellings joined by one space. The following `0xffffffffffffffffULL` is one pp-number, selects `unsigned long long int`, and emits `FFFFFFFFFFFFFFFF`; `'π'` decodes to U+03C0 and emits an ordinary `int`, `C0030000`.
- Ownership/lifetime: the input buffer lives through the invocation; phase/token lookahead is bounded; ordinary token spellings are callback-local; only the pending string run survives callbacks. Flush-time descriptors and code-unit bytes are transient and are released with the run. The fixed keyword/type maps contain bounded metadata. Storage is O(input + active token + largest adjacent string run + emitted bytes), with a constant number of linear copies for a retained string run. There are no semantic/template caches, IR/MIR, optimizer, generated executable, or cache-invalidation paths in this stage. Those architecture and optimization checks are inapplicable here.
- Source-to-output work is linear in source/token/code-unit/output size after the audit fixes below: phase/token scan is streaming; UDL suffix search/validation is bounded to one candidate; literal parsing uses a fixed number of grammar scans; vector/string growth is geometric. No fixed-point pass, unbounded search, whole-program retry, or code-growth transform exists. There is no optimization legality/profitability/invalidation pipeline or IR work/growth budget to apply to a tokenizer.

## Behavior and coverage

The PA2 behavior groups are implemented: C++11 keywords/alternative operators and invalid preprocessing tokens; decimal/octal/hex integer grammar, suffix/type/range selection and numeric UDLs; decimal floating grammar with the mandated `PA2Decode_*` adapters; ordinary/encoded/user-defined character literals; and raw/non-raw strings, numeric-vs-scalar escapes, UTF-8/16/32 code units, maximal phase-6 concatenation, encoding-prefix consistency and UDL-suffix consistency. The existing large-concatenation case is included in the independent performance review. All 26 course PA2 fixtures are retained and pass.

## Independent findings and changes

1. **A valid one-character UDL suffix was rejected.** `valid_ud_suffix` required at least two bytes, rejecting `_` itself for pp-number, character, and string UDLs. N3485 [lex.name] §2.11 defines `identifier-nondigit` to include `_` and permits an `identifier` consisting of that one character; [lex.ext] §2.14.8 uses `identifier` as `ud-suffix`. Thus `1_`, `'a'_`, and `"a"_` are lexically UDLs (later semantic lookup is outside PA2). The reduced source and exact expected output are in `student.tests/pa2-audit-single-underscore.{t,expected}`. The implementation now accepts `_`. No course reference or comparison rule was changed; the checked-in suite did not cover this case. Reference behavior was observed only as corroboration, not used as the proof.
2. **Malformed pp-number UDL probing was quadratic.** `try_ud_number` tried every underscore, repeatedly copying and validating the remaining suffix and rescanning the prefix. For `1.a` followed by N underscores, the pp-number remains a single malformed token, every candidate suffix scans a long tail, and the prefix can never be a numeric literal after an earlier underscore. [lex.ext] §2.14.8 makes the suffix an identifier and requires the preceding literal grammar; no later underscore can repair an earlier underscore already included in that prefix. The implementation now examines only the first underscore, validates at most one suffix and the two numeric prefix grammars. `student.tests/pa2-audit-number-work.py` is the reduced 50,000-character case; it checks exact `invalid` output and successful completion. The 20,004-byte frozen performance case measures the original quadratic path against the bounded linear path.
3. **Every output line explicitly flushed.** `DebugPostTokenOutputStream` used `std::endl` for every token. Replacing it with the same newline byte avoids an unnecessary flush per emitted token; standard stream completion still flushes at normal process exit. Exact-output/status checks on all PA2 fixtures and the fixed performance inputs establish behavior preservation. The change reduced the measured tool `.text` rather than growing it.

No reference sidecars, source inputs, exit statuses, coverage, or comparison rules were modified. No C++11 reference-output correction was needed, so the exception's bundle-revision procedure was not invoked.

## Performance evidence and acceptance

The former checkpoint plan's 3.93 s / 185,624 KiB rebuild, 0.16 s / 4,268 KiB on `700-hard-string-concat.t`, and 152,024-byte `.text` are preserved as single-run observations only. They had no frozen A/B or noise calibration and are not gates or comparative claims. The earlier PA1 plan's 1% text/RSS limits were likewise self-imposed and already reclassified as non-binding measurements; PA2 has no mandated numeric performance threshold. Acceptance here is correct output plus a repeatable benefit on affected work, bounded linear work, and no disproportionate compiler-memory or text growth.

No transform introduces IR growth, runtime speculation, or invalidation risk.
