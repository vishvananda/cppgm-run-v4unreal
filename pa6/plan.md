# PA6 final audit — scopes and canonical types

## Stage, history, and acceptance boundary
- **Stage base / previous checkpoint:** `782b9b53712785fbd9ed1111f77c7b7e0b9da4b2` (PA5 final audit).
- **PA6 implementation commits reviewed:** `2ee2fbc52` (stage marker/initial plan) and `5c7bdd632` (semantic scopes and types). This is an independent source/history review, not an acceptance of the prior handoff.
- **Scope:** the delivered PA6 surface ends at `cppgm++ --emit-types`: preprocessing, one PA5 structured parse, a TU-local semantic graph, and a deterministic text adapter. PA6 creates no executable, LowIR, MIR, ELF object, or generated C++ program. Those later production stages and executable runtime/text-size claims are not certified by this PA.
- **Spec alignment:** the emitted text is a view, not a semantic transport. `build_semantic_model(SyntaxTree&&)` now consumes the structured AST, releases its arena and token tape after semantic facts are built, and retains source buffers/packed locations with a stable-ID `SemanticModel`. The dump writer and later phases can query NameId, TypeId, ScopeId, EntityId, canonical function-signature and overload-identity IDs, bindings, source locations, namespace edges, bases, and source files without parsing the dump. No IR text roundtrip or cloned syntax tree is used. A separate Analyzer/model and parser are owned per translation unit.

## Reconstructed architecture and representative flow
1. The PA4 preprocessing path streams expanded tokens into one compact `PostTokenBuffer`; the driver scopes that token tape to parsing. `parse_syntax_tree(..., semantic_mode=true)` constructs one arena-backed PA5 tree and transfers immutable source-file owners and packed file/offset locations. PA5's bounded speculative lookahead remains the only parser rollback budget; the PA6 class scan is a token hint scan, not a second grammar parse.
2. The semantic pass visits structured nodes once in source order. Names are interned to NameIds; scopes, entities, bindings, types, complete function types, and parameter-only overload identities use TU-local stable IDs. Scope children are indexed by `(scope-kind, NameId)`; declarations by NameId; typed identity indexes compare structured fields after hashing, never rendered type strings or serialized IR. Using/inline/anonymous namespace edges are traversed by a deduplicated per-lookup worklist. Class inline function bodies are deferred until later member declarations have been registered for the C++11 complete-class context; grammar is not replayed.
3. Example trace in `student.tests/pa6-final-audit.cpp`: `enum class Width` creates an enum TypeId and enum ScopeId; earlier enumerators are looked up in that enum scope, and `two = one + 1` / `three = Width::two + 1` establish values 2 and 3. `static_cast<int>(Width::three)` reaches the integral evaluator and static assertion. The type-ID/name view, enumerator values and scope are emitted from the same model.
4. The same reducer defines an outer namespace `Qualification` and a nearer class of the same name in `Nested`. `Nested::Qualification::Value` resolves to the class scope/type (`int`), not the outer namespace's alias (`char`). In `hidden_type_lookup`, a block variable named `Hidden` does not erase the class entity used by `struct Hidden *pointer`; the binding retains a pointer to the original class TypeId.
5. `ConstIntReference` traces an aliased const reference to a constexpr object into an array bound. `ReferenceMember`, ordinary single inheritance, virtual-function vptrs, and static data-member redeclarations exercise the x86-64 type-forming layout facts. `decltype(nullptr)` exercises the type-id path to canonical `nullptr_t`.
6. After graph construction, the SyntaxNode arena is destroyed, but Binding/Scope/Entity records keep packed locations and the model owns the immutable source-file buffers until model destruction. Dump ordering uses source-ordered vectors; hash-table iteration never determines output order. Per-TU model destruction is the release point.

## Findings and cohesive changes
| Finding | Change / evidence |
|---|---|
| Type and function indexes used serialized string keys; class/enum/template-parameter facts could conflate identities; one function-signature ID conflated return types and overload identity. | Replaced serialized keys and per-key collision vectors with a flat open-addressed `FlatIdentityIndex` and structural equality over TypeIds, flags, NameIds, and child TypeIds. `SmallIntList` keeps the common parameter list inline. Canonical function-type signatures include the return type and adjusted parameters; a separate parameter-only overload identity drives compatible redeclaration matching. Template parameters include their owning parameter ScopeId. |
| Reopening/find-child operations linearly scanned all siblings; compatible redeclarations/imports allocated and abandoned duplicate Entity records. | Added a flat `(kind, NameId)` child-scope index. `add_binding` accepts an existing EntityId, so redeclarations, using declarations and injected anonymous-union members reuse identity without orphan entities. A wide-scope frozen benchmark exercises the former sibling-scan path. |
| Category-filtered lookup could skip a nearer value and fall through to a parent type; namespace-only lookup must nevertheless find an outer namespace past a same-spelled value. Qualified lookup could select an outer namespace instead of a nearer class. | Direct ordinary-name declarations now hide outer type lookup, namespace-target lookup remains separate as the course requires, and qualified components select the nearest valid namespace/class/enum scope. `struct T` elaborated lookup independently finds a hidden class entity. Reducers and all course references pass. |
| Scoped-enum `&&`/`||` left operands were accepted when short circuit skipped evaluation; an unselected RHS could hide scoped-enum conversion/comparison errors. Scoped enumerator initializers missed prior enumerators. | Added a non-evaluating scoped-enum expression-type walk for skipped operands and initializer conversions; it still permits `0 && (1/0)` and `1 || (1/0)`, but rejects invalid enum conversions/comparisons and unknown names. Evaluator context recognizes prior same-enum enumerators as integral values during enumerator initialization. `constexpr` declarations now require supported constant values, including values through const-reference aliases. |
| `const void`/aliased cv-void objects and arrays/references were not rejected; `decltype(nullptr)` in a type-id was misparsed as an expression; nullptr_t was not available to type sizing. | Void checks strip cv and are shared by object/array/reference construction. `decltype` is a definite type start in `sizeof`; type-id normalization preserves its specifier and produces the guide's `nullptr_t` type, size and alignment. |
| Type-forming layout counted reference members as referent storage and repeated out-of-class static member definitions as subobjects; base scopes were not retained. Anonymous source-point naming rescanned bytes from file start per node. | Reference members use the target x86-64 pointer slot while `sizeof(reference-type)` remains referent size. Base type IDs, simple non-virtual base layout, empty-base/tail-padding facts and vptr facts are retained; duplicate EntityIds count once, so a static member definition does not add storage. Anonymous source-point names use a per-file line-start cache and a file discriminator, avoiding repeated prefix rescans and cross-file collisions. |
| The semantic graph was private to a text writer, and AST/token/source lifetimes were coupled. | Added the read-only, stable-ID `SemanticModel` API and made `--emit-types` a writer over that model. The parser/token block ends before semantic analysis; graph construction releases the syntax arena, while source owners/locations remain with the model. `student.tests/pa6-semantic-model-api.cpp` checks IDs, lookup, source-file ownership and source locations; it also passes an AddressSanitizer build/run. |

No course fixture, reference output, status sidecar, comparison rule, or coverage was changed. No reference correction was made and no bundle revision applies. The C++11 reducer was compiled with the host C++11 frontend as a syntax/ABI check, not used as production behavior or as sole proof. Rules applied include N3485 `[expr.log.and]`/`[expr.log.or]` (contextual bool conversion), `[dcl.enum]` (scoped-enum conversion and enumerator rules), `[dcl.constexpr]`, `[basic.types]` (void remains incomplete), `[dcl.type.elab]` (elaborated class lookup), `[basic.scope.class]` 3.3.7/1, and `[dcl.fct]` parameter adjustment. Target class/reference sizes are x86-64 ABI facts, not universal C++ size mandates.

## Complexity, validity, and bounded work
- Parser grammar processing remains one pass; the existing PA5 aggregate lookahead cap is 4 visits per input token. PA6's complete-class token hint scan jumps matched braces and does not parse or clone declarations.
- Direct name/child lookup and canonical type/signature interning are flat open-addressed tables with average O(1) lookup; collisions compare typed records. Type/name/signature identity does not depend on rendered text. Scope vectors preserve deterministic source order.
- Namespace lookup work is proportional to reachable directive/inline/anonymous scope edges and uses epoch marks to process each reached scope once. Lookup has no persistent result cache, so declaration/using-edge invalidation is not an issue. Layout facts are computed once after class completion; declarations cannot append class members afterward.
- Constant evaluation visits only required integral expressions, observes short-circuiting while still validating operand types, and rejects signed overflow/invalid scoped-enum operations in its supported subset. Unknown facts are not upgraded to stronger optimizer promises.
- No PA6 optimization level, IR pass, inliner, or code-growth budget exists. Selection, allocation, executable runtime, generated-program text size, and optimizer legality/profitability are inapplicable here; no IR-node-count or executable-speed claim is made.
