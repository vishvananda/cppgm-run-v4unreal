# PA1 implementation plan and final audit

- Stage base: `e50e87639188c5da678ab00d4d927c5d57396c65`. Final independent audit covers implementation/handoff commits `6a3a8518c`, `094296730`, and source/test fix commit `6961c35ff`.
- Spec alignment / reconstructed architecture: `dev/pptoken.cpp::main -> PPTokenizer::tokenize -> Lexer::run -> IPPTokenStream` reads one immutable UTF-8 source buffer. `Phase12Cursor` performs UTF-8 decoding, trigraph replacement, phase-2 splicing and required EOF-newline handling with bounded queues and physical ranges. `Lexer` has bounded logical-token lookahead, UCN normalization, line/directive context, comment/newline handling, maximal token scanners, and raw-string mode. Its typed callbacks emit directly; the CLI `DebugPPTokenStream` is an output adapter, never an input to a later phase. Trace 1: `??=include <x>` becomes `#`, recognizes line-start `#`/`include`, and reports `<x>` as a header name. Trace 2: `R\\\n"(??=body)"x` uses the post-splice logical `R"` opener, preserves `??=` in the raw body, then emits the suffix as a user-defined string token. `PPTokenizer` retains no token vector; live state is the source, bounded lookahead, active spelling, at most 17 raw-delimiter code points, and bounded immutable Unicode tables. A long token may require an equally long temporary string under the existing callback interface. Scanning is linear in input/output with fixed-size operator/range tables and at most 16 delimiter characters. No semantic graph/template demand, caches or invalidation, LowIR/MIR, optimization, allocation or ELF emission exists in PA1; those checks are inapplicable.
- Findings fixed: (1) a terminal backslash was returned as a token because final LF insertion happened after phase 2. N3485 §2.2(2) requires the inserted newline to participate in splicing. The cursor now detects a required appended LF before final-splice handling, including a terminal `??/` trigraph and a physical final `\\\n`. Reducers cover `a\\`, `a\n\\`, `a\n\\\n`, and `a??/\n`. (2) raw scanning assumed `R`/prefix and quote were adjacent in source bytes. N3485 §2.5(3) makes raw recognition follow phase-2 tokenization but reverts transformations only between the quotes. The scanner now obtains the logical quote's physical range, emits the translated prefix and scans raw source after the quote; `R\\\n"(body)"x\n` and `u8R\\\n"(body)"x\n` pass, including subsequent physical location checks.
- Earlier reference correction independently reviewed: `student.tests/pa1-block-comment-newlines.t` reduces `/*\nbody\n*/x\n`. N3485 §2.2(3) says each comment becomes one space and new-line characters are retained, proving the bundle's dropped newlines wrong. Only `pa1/tests/100-extra-comments.ref` and `900-real-world.ref` were corrected; sources, statuses, comparisons and 54-test coverage remain unchanged. Bundle source revision SHA: `c2f713cd70d06170632bfde3e75dd6fe1aa44d98`.
