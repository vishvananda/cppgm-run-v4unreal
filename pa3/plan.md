# PA3 implementation plan and final independent audit

## Scope, history and reconstructed architecture

- Stage base: `58db569f36226e077d7d54c1f6bff3767eebde22`. This final audit independently covers implementation `efe44af14`, its validation/performance handoffs `6e4c5140d` and `88c0d47e6`, and the source delta recorded below. The previous checkpoint review is context, not a substitute for this audit.
- PA3 is the standalone `ppexpr` tool, not the C++ semantic/template/LowIR/native pipeline. Its actual path is `ppexpr.cpp` (one owning UTF-8 source buffer) -> `PPTokenizer` phase-1/2 cursor and phase-3 lexer -> borrowed typed `IPPTokenStream` callbacks -> one current-logical-line typed token vector -> recursive-descent evaluator -> formatted value/error and final `eof`. The tokenizer does not materialize a post-token stream, and PA3 does not serialize/reparse tokens or IR.
- Representative data-flow trace: source `1 + 2 * 3 == 7 || 0` is phase-translated and delivered as pp-number/operator callbacks. On each number callback the evaluator validates the C++11 integer spelling/type and retains only a `Value` (64-bit bits plus signedness); operators become enum IDs. At line end the precedence parser computes `2*3`, then `1+6`, comparison and logical result, and emits `1`. For `defined(and)`, the alternative-token callback retains operator identity plus identifier-operand/first-byte parity, so `defined` evaluates the mock rule without preserving its spelling. `u'π'` is parsed in its callback into the unsigned `char16_t` value 960. The line vector is cleared after evaluation; its geometric high-water capacity is reused for subsequent lines and released at tool exit.
- The immutable source buffer remains owned by `main` through tokenization. `PPTokenizer` borrows it and callback spellings are borrowed/transient. The audited change removes all owning lexeme strings from retained tokens: tokens now carry a small tag, `Value`, operator enum, identifier category and the parity fact needed by mock `defined`. Numeric/character conversion occurs during callback consumption; generic identifiers retain only facts needed by this grammar. This avoids duplicate original/canonical string copies and owning strings per retained token while preserving callback lifetimes; lexeme/parser scratch remains callback-local and transient.
- Parsing is one pass over each line with fixed precedence levels; binary chains are iterative/left-associative and conditional/unary/parenthesized nesting is guarded at 2048. Line handling and parser work are O(input bytes + produced tokens), with geometrically grown storage bounded by the largest logical line. Malformed expressions and course-defined divide/modulo-by-zero or invalid shift counts become line-local `error`; phase-1/2/3 failures propagate to the CLI and return failure. Logical/conditional branches are parsed but evaluated lazily, preserving type information from both conditional arms.
- This PA has no declarations/scopes, templates, semantic caches/worklists, LowIR/MIR, optimizer, allocator, ABI lowering or ELF output. Those architecture, optimization legality/profitability/invalidation and compiler-wide work/growth-budget surfaces do not exist in PA3 and are not waived for later stages. There is no generated C++ program from `ppexpr`; generated-program runtime/text and the later fixed compiler workloads are inapplicable. The applicable executable benchmark is the PA3 evaluator itself, reported below.

## Independent finding and change

- The handoff implementation retained both `spelling` and `original_spelling` as owning `std::string`s in every line token, including operators and ordinary identifiers. It also parsed numeric/character token spellings only after building that text-token vector. This duplicated token text and made per-token storage/allocation disproportionate, especially for a single long logical line. It conflicted with the spec's compact typed-fact/data-ownership direction and was visible in PA3's complete callback-to-evaluator path.
- Replaced those records with compact typed tokens. Literal values are decoded immediately from borrowed callbacks; operators use enum identities; identifiers retain only `true`/`false`/`defined` class, generic-identifier status and the first-byte parity needed by `defined`. Alternative operator identifiers preserve both operator and identifier-operand semantics; `new`/`delete` are mapped back to identifiers as required in preprocessing-token context. No reference output or test coverage was changed.
- Reviewed integer literal candidate/type selection for the x86-64 C++11 ABI, character prefixes and signedness, signed/unsigned common conversions, precedence/associativity, all short-circuit and conditional paths, line/error isolation, and the PA2-to-PA3 borrowed callback handoff. Existing outcomes are unchanged on all 20 course fixture inputs and their checked references, plus 30,000 deterministic generated grammar expressions (A/B exact-output comparison). The focused semantic-group test also matches byte-for-byte.
- No reference correction was indicated: no reduced reproducer plus cited C++11/LowIR proof established any reference as wrong. Therefore no reference output or bundle revision was altered; reference-policy exception procedures were not invoked.

## Performance evidence and acceptance

There is no mandated numeric PA3 performance threshold or optimization pipeline. Earlier PA1/PA2 self-imposed text/RSS limits remain non-binding historical measurements as documented in those audits; the PA3 checkpoint's uncalibrated single-version timings were not used as a comparative claim. For this audit, A is the frozen pre-audit PA3 binary from `efe44af14` (`g++`, `-std=gnu++11 -Wall -O3`, make's test-runner build mode), SHA-256 `b7b447123c70a2da473e21d4404c559204331af0c3ab27d02e2e0c63262e67df`; B is the audited build with the same flags/mode, SHA-256 `5a0cb6484c1c379dd123914e14f3103958aef10a64517fdf5ca7ef4e04486689`. Inputs and outputs were frozen and checked before timing; all observations are retained under `$RALPH_ARTIFACT_DIR/pa3-final` (`audit-abba.json`, `wide-abba.json`, RSS and section-size files, binaries, inputs and outputs).

|---|---|---|---|---|
| 200,000 arithmetic/logical lines | 4,000,000 B / `a27623dc1ae57710cdf480324fab963e8203540d2b5676433d62aefba6901380` | 400,004 B / `dbf17a3d345eb111023d6b231dd0eabe0f6e60f40e192f2e9848539bcbbb137b` | 0.30% / 5.83% | 1.667686 s → 1.517049 s; 9.30% (8.79–10.29%); all seven blocks favor B |

Both workloads used wall-time A/A noise calibration (eight same-binary pairs) and seven ABBA blocks (`A1/B1/B2/A2`), with unchanged frozen flags/inputs and equivalent output. The wide-line calibration includes one disclosed outlier; even the smallest paired ABBA improvement (24.82%) exceeds its 19.53% maximum A/A pair delta. The simple workload's smallest improvement (8.79%) also exceeds its 5.83% maximum A/A delta. Thus the latency benefit is repeatable and attributable to the compact token path, not merely fewer IR nodes or a single favorable observation.

Peak RSS was sampled in alternating A/B/B/A/A/B order. On the 4 MB line workload A was 11,264/11,240/11,184 KiB (median 11,240) and B 11,196/11,116/11,204 KiB (median 11,196); ranges overlap and there is no material change. On the wide-line workload A was 86,600/86,736/86,736 KiB (median 86,736) and B 45,744/45,480/45,708 KiB (median 45,708), a 47.3% median peak-RSS reduction. `size -A` reports `.text` 126,502 B (A) versus 108,582 B (B), down 14.2%; total ELF section bytes are 154,379 versus 135,453, down 12.3%. The measurements support both actual evaluator latency improvement and lower wide-line memory use, with no text growth. Since this tool emits values rather than compiled programs, native generated-program runtime/text and optimizer legality/profitability/growth budgets are not applicable.
